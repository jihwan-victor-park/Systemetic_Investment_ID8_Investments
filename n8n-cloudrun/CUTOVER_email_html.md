# n8n cutover: use the backend's email

`ID8_PB-Attio_corrected.json` replaces the live `ID8 PB-Attio` workflow. This is
the one change in the takeover with a visible result and almost no blast radius,
because it moves work the backend **already does** into the place that already
consumes it.

Generated by `build_corrected_workflow.py` from the live export. Node ids,
positions, credential references and webhook ids are byte-identical to the live
workflow, so this imports over it rather than arriving as a stranger.

## What changes

| | Live today | Corrected |
| --- | --- | --- |
| Nodes | 27 | 24 |
| Intake email HTML | built in 3 near-identical Code nodes (~500 lines of JS) | `{{ $('HTTP Request').item.json.email_html }}` |
| Fit scores in the email | PitchBook only, and only if the Code node's fields happened to match | every flow, from `email_format.py` |
| Re-seen deals ("already in Attio — updated") | never rendered | rendered |
| Below-mandate filtered deals | never rendered | rendered |
| Logo | `pb-attio-pipeline.onrender.com/logo` (dead Render host) on 3 of 4 emails | backend's own `/logo` |
| Jesse daily digest | **computed, then discarded** — `Code in JavaScript2` had no outbound edge | `Code in JavaScript2 → If3 → Send a message2` |
| Error email | `Send a message4` had `{"options": {}}` — no recipient, subject or body | full alert with workflow, failed node, execution link |
| `Code in JavaScript4` | increments `staticData.changeCount`, never read | removed |
| `emailType` | unset (relying on the node default) | explicit `html` on all 5 Gmail nodes |
| Active on import | — | `false`, deliberately |

Not changed: recipients, credentials, Drive folder ids, the Sheet id, polling
frequency, the four backend endpoints, binary-upload shape, and the per-row
Jesse HTTP loop.

## Why the backend's email is the correct source

`pipeline/app.py`'s `_run_pipeline_worker` builds `email_html`, `email_text` and
`email_subject` for every flow, and its own comment says n8n "now just uses
`{{ $json.email_html }}`". That was written, and the n8n side never followed.
The result was three copies of a template that had drifted apart — only the
PitchBook one rendered fit scores, and none of them could render a re-seen deal,
because those fields did not exist when the templates were written.

One renderer, in the language the deal objects already live in, covered by the
existing `deal_intelligence` tests. n8n goes back to being transport.

## The skip guard

The old Code nodes returned `{skip: true}` when `deals.length === 0` and the IF
checked `$json.skip != "true"`. Reading the HTTP response directly needs **two**
conditions, combined with AND:

```
{{ $json.deals?.length || 0 }}   >  0          preserves "nothing found, no email"
{{ $json.email_html }}           notEmpty      guards the timeout case
```

Both are load-bearing:

- The backend builds `email_html` **unconditionally**, including for a zero-deal
  run — so `email_html notEmpty` alone would start mailing empty digests.
- If a Stage 1 batch runs past `_start_pipeline`'s ~1700s budget, the response is
  the **partial** state (`status: "screening"`) with no email rendered yet.
  `deals.length` alone would pass and mail an empty body.

`?.` and `|| 0` because an error response has no `deals` key at all.

## Jesse digest guard (a behaviour choice)

`Code in JavaScript2` renders "None" when nothing new arrived, so simply
reconnecting it would mail a no-op every day. The new `If3` gates on
`newCount > 0` — the same shape the repo's own abandoned webhook variant
(`ID8_PB-Attio_webhook.json`) already used.

**To get a digest every day regardless**, delete the `If3` node in the n8n
editor and connect `Code in JavaScript2 → Send a message2` directly. Nothing
else depends on it.

## Import procedure

Do this on a **quiet day**, not a Monday morning when the PitchBook drop lands.

1. **Export the live workflow first.** n8n → `ID8 PB-Attio` → ⋯ → Download.
   Keep the file. This is the rollback.
2. n8n → Workflows → Import from File → `ID8_PB-Attio_corrected.json`.
   It imports **inactive**.
3. **Reattach credentials if prompted.** The credential *ids* are preserved, so
   normally nothing is asked. If the Gmail/Drive/Sheets credentials are being
   reissued under ID8-owned accounts (see the takeover credential plan), do that
   here in the same pass.
4. **Test one branch before activating anything.** Open the corrected workflow,
   select the Watchlist branch's `Google Drive Trigger`, and use *Execute
   Workflow* with a test file dropped into `Watchlist Drop`. Watchlist is the
   right first branch: one recipient, smallest audience.
5. **Compare the emails.** The new one should show everything the old one did,
   **plus** fit scores, a re-seen section if any deal was already in Attio, and a
   working logo.
6. Deactivate the old workflow, activate the corrected one. Never both — three
   Drive triggers polling the same folders every minute would process each drop
   twice.

## Rollback

Deactivate the corrected workflow, re-import the export from step 1, activate
it. No backend change is involved, so there is nothing to roll back on Cloud
Run — the backend has been returning these fields all along; only n8n's use of
them changes.

## Verifying the guards

`n8n-cloudrun/tests/test_corrected_workflow.py` asserts the structural
invariants against the committed JSON: no dangling connections, no orphaned
nodes, no `$('...')` expression pointing at a deleted node, every Gmail node
fully configured and set to HTML, no `onrender.com`, the four endpoints
unchanged, and the Drive/Sheet ids unchanged. Run with `pytest`.

n8n reports none of these at import time — it accepts the JSON, activates, and
silently does nothing on the broken path. That is precisely how the Jesse digest
went missing.
